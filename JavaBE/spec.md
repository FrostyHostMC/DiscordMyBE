# Project Name

Parity Texture Auditor

## Concept

An intelligent, data-driven Java-to-Bedrock conversion engine that dynamically analyzes mod archives to synthesize Bedrock content. It replaces hardcoded mod-specific logic with a universal, evidence-based analysis pipeline that preserves source provenance and ensures 100% schema integrity without relying on predefined content patterns or mod-specific exceptions.

## Gameplay

- **Core Loop**: Universal Source Discovery -> Semantic Analysis -> Intermediate Representation (IR) Synthesis -> Capability-Aware Translation -> Automated Validation -> Provenance-Tagged Export.
- **Goal**: Achieve maximum parity between Java source mods and Bedrock output by dynamically inferring item/entity/block semantics from bytecode, metadata, and resource structures. The engine enforces strict schema correctness, eliminates phantom references, and provides honest reporting on unsupported mechanics.
- **Special Mechanics**: 
  - **Provenance-First Architecture**: Every generated component is tagged as SOURCE, ADAPTED, SCAFFOLD, or INVENTED. Parity metrics strictly exclude INVENTED content.
  - **Evidence-Based Analysis**: Replaces generic mob/item profiles with data extracted directly from source classes, interfaces, and registry declarations.
  - **Bounded Self-Healing**: A multi-pass validation loop that repairs schema mismatches (e.g., UV mapping, render controller nesting) while reporting remaining anomalies as UNRESOLVED.
  - **Universal Asset Resolver**: Recursively traverses mod archives to link authentic textures, geometry, and sounds, ensuring zero hardcoded paths.
  - **Capability-Aware Translation**: A version-aware system that checks target Bedrock schema support before attempting translation, preventing the generation of invalid Molang or unsupported components.
  - **Regression Guard**: A persistent verification suite that blocks export if schema-critical rules (e.g., identifier namespacing, atlas coverage, manifest integrity) are violated.
  - **Playable Mode Gating**: A master toggle that prevents the generation of "invented" gameplay content (AI, behaviors, spawn rules) when source evidence is absent, ensuring the audit remains a diagnostic tool rather than a content generator.
  - **Semantic Classification Engine**: A dynamic, evidence-driven system that classifies items based on source inheritance, interfaces, and interaction logic rather than generic templates or name-based heuristics.
  - **Universal Animation Bridge**: A capability-aware animation translator that maps Java-native bone transformations and keyframe data to Bedrock-compatible animation controllers. This bridge utilizes a granular mapping layer to dynamically bind source track transformations to the Bedrock player skeleton, ensuring custom player animation mods are mapped bone-for-bone without hardcoded templates or fixed-rig assumptions. The bridge includes a monitoring sub-system that flags unmapped bone references, allowing for the iterative expansion of a common Java-to-Bedrock bone alias table to ensure high-fidelity translation of complex player animation mods.
  - **Post-Processing Validation Pass**: An automated safety layer that executes after pack generation to sanitize sound paths, update item schema versions, prune unsupported Molang queries, verify manifest integrity, and enforce correct texture atlas mapping, ensuring all generated packs meet current Bedrock engine requirements.
  - **Animation Porting Protocol**: A strict porting workflow requiring verbatim copy of animation/geo/sound/texture JSON, mandatory entity wiring (player.entity.json), translation of Java triggers to valid Bedrock Molang, unique ID enforcement, and pre-packaging validation.
  - **Automated PBR Synthesis**: A specialized pipeline that scans Java resource packs for PBR-compliant texture maps (Normal, Specular, Emissive). The engine automatically maps these to Bedrock’s Deferred Rendering schema, generating the necessary `materials.json` definitions and ensuring texture atlas alignment for all identified PBR assets.
  - **Automated Texture Normalization**: A structural repair protocol that detects legacy `textures/item`, `textures/entity/mob`, `textures/models/entity`, `textures/models/armor`, or `textures/gui` directories, migrates all assets to the standard `textures/items`, `textures/entity`, `textures/models/armor`, or `textures/gui` paths, and performs a recursive update of `item_texture.json`, `entity` definitions, `attachables` components, and associated component references to maintain atlas and render integrity.
  - **Armor Mapping Validation**: A specialized pass for `textures/models/armor` that verifies legacy armor texture paths against Bedrock `attachable` component definitions, ensuring that texture-to-slot bindings are correctly registered in the `attachables` JSON schema to prevent rendering failures.
  - **Mob Linking Protocol**: For every entity, the engine reads its renderer and model classes to extract model, texture, and animation resource strings. It binds these specific files to the mob, ensuring that recovered models are never replaced by generic fallback rigs. The engine performs a recursive search across all `assets/*/textures/**` directories to locate assets matching these extracted strings, treating unreferenced but matching files as valid resources to be migrated to `textures/entity/` and linked.
  - **Animation Ownership Protocol**: Animation clips are strictly bound to the entity whose model or animation class loads them. Clips are attached to the owning entity's client entity definition. Mapping to the player is restricted exclusively to cases where the owning class is a player model or animation; no generic player.entity.json generation or merging is permitted.
  - **Geometry ID Enforcement**: Geometry identifiers are strictly formatted as `geometry.<name>` without colons. The engine maintains a single registry and performs a global rewrite of all references upon renaming, followed by a mandatory resolution check for every client entity.
  - **Spawn Egg Logic**: Spawn egg base and overlay colors are extracted directly from Java registration data and injected into the client entity definition. The engine enforces `is_spawnable: true` and `is_summonable: true` for all entities, ensuring they appear in the creative inventory. If color data is missing, it generates deterministic colors based on the entity identifier to ensure spawn eggs are always functional and visible.
  - **Universal Schema Auditor**: A runtime diagnostic layer that intercepts engine-level warnings (e.g., missing icon textures, invalid render controller arrays, particle load failures, and script version mismatches). It dynamically maps these to a global correction registry that enforces `item_texture.json` registration, sanitizes `render_controllers` syntax, and aligns script dependencies to the highest supported API version, ensuring that any Java mod's structural gaps are filled by standardizing against the current Bedrock schema.
  - **Universal Script Dependency Resolver**: A dependency-graph analysis engine that maps all `@minecraft` module requirements across the behavior pack. It performs a topological sort of version constraints to identify the highest common denominator version compatible with the host environment, automatically injecting the correct `manifest.json` dependencies and flagging irreconcilable version conflicts as build-time errors rather than runtime failures.
  - **Generalized Particle Converter**: A structural mapper that parses Java particle JSON/class definitions to extract emitter, texture, and motion parameters. It maps these to valid `minecraft:particle_effect` structures. If a particle property lacks a direct Bedrock equivalent, the converter logs a diagnostic warning and excludes the property, ensuring the resulting JSON is schema-compliant and functional.
  - **Generalized Sound Mapping**: A recursive sound-event resolver that maps Java-native sound identifiers to Bedrock `sound_definitions.json` entries. It validates sound file existence, maps event triggers (e.g., `fly`, `step`, `hurt`) to valid Bedrock sound event names, and prunes invalid references, ensuring that all sound triggers are backed by actual assets.
  - **Client Entity Generator**: Automatically generates missing `client_entity/*.entity.json` files for all behavior-defined entities, ensuring correct binding of geometry, textures, and render controllers to prevent in-game invisibility.
  - **Item Model Normalizer**: Parses Java `assets/models/item/*.json` parent pointers to distinguish between flat `item/generated` sprites and complex block-based models, automatically updating `item_texture.json` or generating block-model JSONs as required.
  - **Automated Geometry/Mesh Repair**: A deep-scan utility that detects missing bone hierarchies or unmapped vertex groups in imported Java models. It automatically re-parents orphaned meshes to the nearest valid root bone and generates missing `geometry.json` definitions to ensure full body rendering (legs, torso, etc.) in Bedrock.
  - **Universal Rig-to-Bone Mapper**: An automated skeletal analysis tool that scans Java entity model files for bone hierarchies. It dynamically generates Bedrock-compatible `geometry.json` files by mapping Java bone names to standard Bedrock skeletal structures, automatically creating missing bone nodes to ensure complex models (multi-limbed entities, articulated armor) render correctly without missing parts.
  - **Universal Poly-Mesh Converter**: A high-fidelity geometry pipeline that performs automated vertex-weighting and bone-skinning translation for complex 3D models. It maps arbitrary Java mesh structures to Bedrock-compliant skinning, ensuring that multi-part entities (e.g., complex bosses, articulated armor) maintain full skeletal integrity and animation fidelity across all frames.
  - **Intent-Based State Machine Translator**: A logic-parsing engine that extracts Java-side animation state machines and converts them into Bedrock `animation_controllers`. This enables the porting of complex combat behaviors (dual-wielding, custom stances) by mapping Java triggers to valid Molang expressions.
  - **View-Model Mapping Protocol**: Automatically detects first-person-specific models and animations, wrapping them in dedicated Bedrock `attachable` components bound to the player camera to prevent third-person distortion and ensure correct first-person hand rendering.
  - **Dynamic Bone Injection System**: A runtime skeletal expansion tool that detects custom bone references in Java animations (e.g., "wrist_twist") and injects these nodes into the Bedrock player rig during pack generation, bridging the skeletal gap for complex, high-fidelity animations.
  - **Off-Hand Attachable Resolver**: Scans item registries to identify dual-wieldable assets, automatically generating the necessary `attachable` definitions and linking them to the translated animation controllers to enable functional dual-wielding in Bedrock.
  - **Complex Environment/Foliage Converter**: A specialized pipeline for high-density mods (e.g., Conquest Reforged) that maps custom block-model hierarchies, foliage-layer placement logic, and atmospheric lighting data to Bedrock-compatible `geometry.json` and `blocks.json` definitions. It includes an automated "Block-to-Geometry" mapper that converts complex Java block-model JSONs into optimized Bedrock-compliant geometry, ensuring that custom trees, foliage, and environmental assets render with full fidelity.
  - **Foliage & Plant Transparency Pipeline**: A dedicated sub-pipeline for high-density vegetation that automatically detects cross-model transparency (alpha-testing) and maps Java-side vertex-offset animations (wind sway) to Bedrock-native `animation.common.look_at` or custom Molang-driven vertex displacement. This ensures that complex foliage, such as tall grass, vines, and custom tree leaves, renders with correct transparency sorting and fluid movement without breaking the Bedrock render engine.
  - **Robust Animation Normalization**: A post-porting heuristic layer that detects common "broken" animation states (e.g., limb stretching, T-pose lock, or missing bone references) by comparing the exported animation controller against the entity's actual skeletal rig. It automatically prunes invalid bone tracks, re-binds orphaned animations to the nearest valid parent node, and applies corrective scaling factors to prevent geometry distortion during playback.
  - **Rig-Aware Animation Sanitizer**: A corrective layer that specifically targets "stretching" and "floating limb" artifacts by cross-referencing exported animation keyframes against the target Bedrock player skeleton. It dynamically adjusts bone-scale and rotation offsets to ensure that custom Java animations (like those from "Punchy") map correctly to the standard player rig without causing mesh deformation or T-pose locking.
  - **Universal Animation Discovery Engine**: A recursive, format-agnostic scanner that traverses mod archives to identify animation-related resources. It parses JSON, binary, and class-based animation definitions to map skeletal hierarchies, state machines, and dependencies without relying on hardcoded file paths or naming conventions. This engine automatically identifies first-person and third-person systems, binding them to appropriate Bedrock render controllers to ensure high-fidelity playback across all viewpoints.
  - **Universal Animation Interpretation Engine**: A high-level abstraction layer that parses discovered animation data into a unified Intermediate Representation (IR). This IR normalizes timelines, bone transformations (position, rotation, scale), keyframe interpolation, and state machine logic, ensuring that animation behavior is preserved regardless of the source format or version, and enabling accurate translation to Bedrock-native animation controllers. The engine performs exhaustive variable discovery to ensure no animation-driven property is left unmapped.
  - **Universal Variable Resolver**: A deep-scan diagnostic layer that recursively traverses all animation controllers and state machines to identify every variable, parameter, and property reference. It maps these to the Bedrock-native equivalent or flags them for manual resolution if no direct mapping exists, ensuring that "missing variable" errors are eliminated by exhaustive discovery and mapping. The resolver is strictly isolated from procedural expression caches, enforcing a "zero-cache" policy where every expression is re-evaluated against the current archive's IR to prevent cross-mod contamination.
  - **Universal Player Wiring Auto-Initializer**: A critical diagnostic and repair layer that enforces the integrity of the `player.entity.json` wiring. It performs a pre-flight check for the `playerWiring` variable and all associated animation controller hooks. If the variable is missing or the wiring is incomplete, the engine dynamically injects the necessary definitions into the Bedrock player definition, ensuring that custom animations are correctly registered and linked to the player skeleton without manual intervention.
  - **Strict Provenance Enforcement**: A mandatory validation pass that cross-references every generated file against the source archive manifest. Any file or property not directly derived from the source archive or explicitly required by the Bedrock schema is purged, preventing the injection of template-based or hardcoded "phantom" content.
  - **Unified Animation Registry**: A centralized, single-source-of-truth registry that tracks every animation clip from discovery through final export. This registry enforces strict state consistency, ensuring that the counts for "discovered," "registered," "activated," and "exported" animations are derived from the same immutable data set. Any discrepancy between these counts triggers a build-time validation error, preventing the export of inconsistent or "orphaned" animation states.
  - **Anatomical Retargeting Engine**: A semantic-aware bone mapping system that prevents cross-contamination of skeletal regions (e.g., preventing forearm animations from mapping to the head). It enforces anatomical constraints during retargeting, ensuring that limb-specific animations are only applied to structurally compatible destination bones.
  - **Molang Compatibility Analyzer**: A runtime-context validator that intercepts invalid Molang queries (e.g., `query.attack_time` in client-entity contexts) and translates them into supported equivalents or flags them as unsupported, ensuring that all animation logic is valid within the Bedrock engine.
  - **Memory-Optimized Streaming Pipeline**: A non-blocking, asynchronous processing architecture that utilizes worker threads and memory-mapped file streams to handle massive mod archives. It enforces a strict 160MB memory budget by chunking archive traversal, deferring heavy decompiler passes, and utilizing incremental garbage collection to prevent UI thread saturation and application freezes during high-density conversion tasks.
  - **Active Wiring Enforcement**: A mandatory post-conversion pass that validates the `player.entity.json` integration. It forces the injection of `scripts.animate` hooks for all detected animation controllers, replaces invalid Molang queries with engine-supported alternatives, and verifies that the render controller explicitly references the custom animation set, ensuring that ported animations are actually triggered during gameplay rather than remaining dormant. The engine explicitly logs the `controller_path` for every injected animation hook to ensure visibility into the runtime activation chain.
  - **Automated Anatomical Correction**: A high-fidelity retargeting protocol that enforces strict anatomical hierarchy constraints during bone mapping. It prevents cross-region mapping (e.g., limb-to-head) by validating parent-child relationships and transformation spaces against a standard anatomical template. If a source bone lacks a semantically equivalent destination bone, the engine dynamically generates a corrective bone node or applies a transformation-aware approximation that preserves the original animation's intent without causing mesh distortion or T-pose locking.
  - **Universal Tool-Bone Reconstruction**: A specialized resolver for tool and attachment bones (e.g., `DEF_TOOL.R`) that analyzes source animation tracks to determine their functional role. It automatically maps these to Bedrock-native item-attachment points or generates dedicated `attachable` components, ensuring that held-item positioning and auxiliary rig controls are preserved without requiring manual intervention.
  - **Molang Query Translator**: A comprehensive compatibility layer that intercepts and re-writes invalid Molang queries (e.g., `query.attack_time`) into supported, context-aware equivalents. It performs a pre-export validation pass to ensure all translated queries are valid within the target Bedrock client-entity context, flagging any remaining anomalies as build-time errors.
  - **Universal Player-Resource Merge Strategy**: A robust integration protocol that preserves vanilla player functionality (base_pose, look_at_target, etc.) while layering custom ported animations. It ensures that shared player resources are never stripped or overwritten, maintaining full compatibility with both first-person and third-person rendering systems.
  - **Universal Dependency Resolver**: A deep-traversal engine that tracks the lifecycle of every animation identifier, controller, and entity registration. It ensures that every reference is resolved to its final exported location and that all dependencies are included in the final archive, preventing "missing reference" errors in the Bedrock client.
  - **Controller Transition Validator**: A schema-aware analyzer that enforces Bedrock controller syntax, ensuring all transition arrays are valid, states are correctly linked, and no empty or unreachable transitions exist in the final exported JSON.
  - **Universal Animation Reference Auditor**: A mandatory pre-export pass that validates every animation reference (controllers, states, entity registrations) against the actual exported file structure. It enforces a "zero-orphaned-reference" policy, ensuring that every animation identifier used in the player entity or controllers is explicitly defined and registered in the final archive.
  - **Runtime Integration Validator**: A post-export diagnostic pass that performs a structural check of the `player.entity.json` and all linked animation controllers. It verifies that `scripts.animate` hooks are present, Molang variables are initialized, and animation states are reachable, ensuring that ported animations are actually triggered during gameplay.
  - **Universal Controller Transition Repair**: A structural normalization pass that enforces Bedrock schema compliance for all animation controllers. It dynamically prunes empty transition arrays, validates transition logic against state reachability, and ensures that every transition points to a valid destination state. This pass includes a recursive graph-traversal to detect and prune unreachable states, ensuring the final controller JSON is lean, valid, and fully executable by the Bedrock engine.
  - **Universal Player-Wiring Merge Protocol**: A high-fidelity integration layer that performs a deep-merge of vanilla player definitions (`base_pose`, `look_at_target`, etc.) with ported animation controllers. It ensures that custom animations are layered onto the player rig without stripping or overwriting essential vanilla hooks, maintaining full compatibility with both first-person and third-person rendering systems.
  - **Universal Molang Variable Initializer**: A diagnostic and repair layer that identifies missing or unsupported Molang variables (e.g., equipment visibility flags) and injects valid, context-aware definitions into the player entity. It ensures that all animation-driven logic is backed by initialized variables, preventing runtime errors and ensuring that ported animations trigger correctly based on player state.
  - **Runtime Animation Playback Verification**: A post-export diagnostic pass that performs a structural check of the `player.entity.json` and all linked animation controllers. It verifies that `scripts.animate` hooks are present, Molang variables are initialized, and animation states are reachable, ensuring that ported animations are actually triggered during gameplay. This includes a recursive graph-traversal to detect and prune unreachable states, ensuring the final controller JSON is lean, valid, and fully executable by the Bedrock engine.
  - **Automated Animation Wiring Repair**: A critical diagnostic pass that detects "registered but inert" animation clips. It forces the injection of missing `scripts.animate` references into the `player.entity.json` and dynamically updates animation controllers to ensure every registered clip is explicitly bound to a state or script hook, eliminating "nothing plays it" validation defects.
  - **Universal Player-Wiring Auto-Injection**: A mandatory, schema-aware integration pass that dynamically injects vanilla-required animations (`base_pose`, `look_at_target`, `first_person_base_pose`) into the player entity definition if they are missing. It performs a recursive check of all animation controllers to ensure these baseline animations are correctly referenced and activated, preventing "can't find animation" errors.
  - **Universal Molang Variable Auto-Injection**: A diagnostic layer that scans all animation controllers for missing variable references (e.g., `variable.tcos0`, `variable.melee_spear_equipped`, `variable.helmet_layer_visible`, etc.). It automatically injects these into the `player.entity.json` or a global `molang_variables.json` to ensure runtime availability, preventing "unhandled request for unknown variable" errors.
  - **Universal Hand-Slot Normalization**: A translation layer that intercepts `query.get_equipped_item_name` and similar calls, automatically re-mapping Java-style slot parameters to Bedrock-compliant indices (0/1) to ensure valid Molang execution.
  - **Unified Metric Reconciliation Protocol**: A mandatory post-audit pass that enforces a single, immutable `ExportedResourceRegistry`. This registry acts as the sole source of truth for animation counts, bone coverage, and controller states. All diagnostic reports are generated by querying this registry directly, ensuring that "registered," "activated," and "exported" counts are mathematically consistent and derived from the final output archive, eliminating discrepancies between intermediate pipeline stages.
  - **Universal Molang Translation Engine**: A context-aware translation system that recursively parses all Molang expressions. It validates hand-slot parameters (0/1), reconstructs missing variables (e.g., `variable.melee_spear_equipped`, `variable.tcos0`, `variable.helmet_layer_visible`) by tracing source-archive logic, and enforces strict Bedrock schema compliance. This engine ensures that all expressions are valid within the target client-entity context, preventing runtime errors and ensuring high-fidelity animation playback.
  - **Baseline Player Dependency Resolver**: A mandatory pre-flight check that ensures all vanilla player animation dependencies (`base_pose`, `look_at_target`, `first_person_base_pose`) are correctly identified, preserved, and registered in the final player entity definition. This system prevents the stripping of essential player animations and ensures that custom ported animations are correctly layered over the vanilla rig.
  - **Context-Aware Rendering Integration**: A specialized pipeline that distinguishes between first-person and third-person rendering contexts. It ensures that first-person arm poses, item positioning, and camera-bound animations are correctly registered to the first-person render controller, while third-person body movements and locomotion are bound to the standard player rig, preventing cross-context animation artifacts.
  - **Universal Molang Compatibility Engine**: A reusable, source-to-destination translation system that performs deep discovery of variable declarations, tracks execution context, identifies unsupported queries, and reconstructs required runtime variables. It validates hand-slot arguments (0/1) and detects unresolved dependencies before export, ensuring that all ported animations are fully functional and schema-compliant without requiring mod-specific hardcoding.
  - **Universal Molang Slot-Parameter Normalizer**: A mandatory pre-processing pass that intercepts all `query.is_item_name_any` and `query.get_equipped_item_name` calls. It enforces the Bedrock-native two-parameter signature (slot_name, slot_index) by dynamically injecting the correct index (0 for main_hand, 1 for off_hand) based on the source-mod's intended hand-logic, preventing runtime "requires at least two parameters" errors.
  - **Entity Registry Repair Protocol**: A mandatory diagnostic pass that validates all entity registrations against the behavior-pack registry. It forces the inclusion of all spawn-egg and mob-definition logic extracted from Java-side registry classes, ensuring that entities are correctly registered in the Bedrock `manifest.json` and `client_entity` definitions, preventing "missing entity" or "invisibility" errors.
  - **Project Export**: A dedicated "Download Project" button in the dashboard that triggers the packaging of the entire application source code, configuration, and engine assets into a single ZIP archive for manual development and extension.
